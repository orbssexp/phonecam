## HF2 findings to reuse (diagnosis already done; do not re-derive)
- **Restart storm**: the 5 `starting receiver` lines each had a different room id, i.e.
  `new_pairing()` was called 5 times. The QR icon button at the bottom-right of the preview
  regenerates the pairing code on every click with no confirmation, and each click invalidates
  the phone's pairing. Fix: confirm step in the UI + 5 s cooldown; stop and await old workers
  outside the state lock.
- **Relay 409**: `ReceiverHandle::shutdown()` returns before the relay WebSocket closes, so after
  Quit/relaunch the relay still holds the old desktop for the room. Fix: shutdown waits (<= 3 s)
  for the worker, for both the WebRTC and native handles.
- **4K delay**: unbounded mpsc between app and decoder + full-size 4K work per frame (YUV->BGR24,
  naive per-pixel rotation, then bilinear scale to 1080p). Fix: pass a fit box into `dec_decode`
  so the downscale happens inside the colour conversion (no 4K BGR frame ever exists), rotate /
  letterbox at <= 1080p, cap the queue at 3 AUs (drop to the newest keyframe or request one),
  shrink the native events channel. Add per-stage timings to the `[media]` line. Not measured on
  the user's machine yet.
- **Downscale filter** was already swscale bilinear (not nearest), so it is not the quality cause.
- Also in the contract and previously implemented: try all addresses with a 1.5 s timeout, retry
  0.5/1/2 s, precise failure reasons, keyframe request every 1.5 s until live, kbps/lag stats,
  AppState `bitrateKbps` / `source` / `delayMs` + UI rows, version 0.2.0 everywhere.
