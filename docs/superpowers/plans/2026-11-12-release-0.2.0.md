(transport research), "Round H" + "Round H-fix" in `2026-10-30-mvp-contracts.md` (wire protocol

- Keep TCP (method A). Its recommendation (A) is: bound the sender backlog (done on iOS in HF1 at

- Recommendation (B), QUIC datagrams, is a later round and only if Wi-Fi TCP still stutters after
  this release. Custom UDP+FEC, libwebrtc, NDI, SRT, UVC: discarded.

## R2 — auto-update — branch `fin/r2-updater`
Goal: every new release shows up inside the desktop app with a button to install it.
- `tauri-plugin-updater` (+ `tauri-plugin-process` if needed). Endpoint:
  `https://github.com/<owner>/<repo>/releases/latest/download/latest.json` (take owner/repo from
  `gh repo view --json nameWithOwner`). `bundle.createUpdaterArtifacts: true`. NSIS install mode
  passive (the installer is perMachine and elevates; the existing NSIS hooks must keep working).
- Signing key: generate with the Tauri signer into `%USERPROFILE%\.phonecam\updater.key` (outside
  the repo, no password), public key into `tauri.conf.json`. Never print the private key.
- Check in Rust (not in the webview: the window is destroyed when closed to tray): at start and
  every 6 h. New code goes in its own module (`updater.rs`) with minimal hooks elsewhere, because
  another agent is editing `lib.rs`, `state.rs`, `App.tsx`, `ipc.ts` in parallel. Do NOT touch
  version numbers.
- AppState gains `updateVersion: string | null` and `updateProgress: number | null`; IPC
  `install_update` downloads, installs, relaunches. UI: a hairline banner at the top
  "[ UPDATE ] vX.Y.Z available" with an "Install" button and progress; same visual style as the
  app. Tray menu gains "Install update vX.Y.Z" when one is available.
- `scripts/release.ps1 -Version X.Y.Z [-Ipa path]`: fails unless the three version files already
  say X.Y.Z and the tree is clean; builds with the signing key from the path above; writes
  `latest.json` (version, notes, pub_date, `platforms.windows-x86_64.{signature,url}` pointing at
  the release asset URL); `gh release create vX.Y.Z` with the setup exe, its `.sig`,
  `latest.json`, and the ipa when given. Stable asset name without the version is fine if needed
  for the `latest/download` URL. The agent must NOT run the publish step; a `-DryRun` switch that
  does everything except `gh release create` must work and be run once.
- Document in `docs/RELEASING.md` (short): how to cut a release, where the key lives, that losing
  the key means users must reinstall by hand.
Done: `cargo test --workspace`, clippy, `npm run build` pass; dry run produces a signed installer
and a valid `latest.json`; committed and pushed on the branch.

## R3 — USB transport through usbmuxd — branch `fin/r3-usb` (starts after R1 is merged)
- New module in `phonecam-transport`: client for Apple Mobile Device Service on `127.0.0.1:27015`
  (usbmuxd plist protocol: `ListDevices` / `Listen`, then `Connect` with `DeviceID` and
  `PortNumber` in network byte order). After `Result 0` the socket is a raw tunnel to the phone's
  TCP port; run the existing native v1 handshake and framing over it unchanged.
- Phone port: the one learnt from mDNS for the paired phone if known, otherwise 47810.
- Only devices with `ConnectionType` USB. A wrong phone simply fails the HMAC handshake.
- Policy: USB is preferred. If USB becomes available while streaming over Wi-Fi, authenticate over
  USB and switch (the phone replaces its active connection on a new authenticated one; request a
  keyframe). If USB goes away, fall back to Wi-Fi through the normal reconnect.
- If port 27015 is closed (service not installed) log once and keep polling slowly (every 10 s).
- State: `source` = "usb", path label "USB" in the UI.
- Tests: fake usbmuxd server (plist framing, ListDevices + Connect) tunnelling to the fake phone;
  reaches live; Wi-Fi -> USB switch; service absent.
Done: `cargo test --workspace`, clippy, `npm run build` pass; committed and pushed on the branch.
